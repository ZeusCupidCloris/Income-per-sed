# 背景空闲绘制核实与修复

## 原因

本轮先记录实际绘制、鼠标事件和根节点属性变化。无鼠标操作时，主体 class 每帧收到 `compositor-core-active` 的重复写入，旧值与新值相同。背景的 MutationObserver 对每次写入都执行 schedule，导致静止网格持续绘制。原 main 也可复现，不是命名修改新增。

## 修改边界

背景只在相关性能状态实际变化时响应主体 class 变化。网格间距 66、力学、阻尼、鼠标响应、颜色和绘制内容全部保持原值。主题、窗口尺寸、指针输入和后台恢复原入口不变。

不放宽原来的 800ms 空闲绘制最多 3 次断言。新增重复和无关 class 写入测试要求静止画布不重绘，原始画布像素完全相同；同时确认鼠标输入确实改变画布、严重性能状态退出后恢复显示。

透明画布的浏览器截图会合成下面持续变化的数字，因此新增静止检查直接比较画布自身的像素，不把实时数字的变化误判为背景变化。已有全页面截图基线不更新。

## 已核实

- 修复前存在每帧重复属性通知；修复后探针在约两秒观察中只记录一次初始绘制，后续重复通知未再触发绘制。
- 背景专项 4 项通过。
- 连续两次构建，6 个发布文件字节不变。
- Word 仍为 45 页，仅同步网页校验值，原图片与排版保留。

全量本地和远程结果完成后补充。真实跨夜和实体 iPhone/iPad 验收不在本轮范围。

原完整套件在 Windows WebKit 的 `Develop: fun conversions keep whole items at 1440 light` 达到原有 45 秒总时限。轨迹表明，长数量、缩放和零数量的断言已通过，恢复普通工资的保存也已完成，但最终滚动及恢复断言没有执行完；该次完整检查保持失败，不因 Edge 或其他场景通过就改写结果。

只将四个 1440px 宽屏用例拆为“超长数量”和“缩放后归零及恢复”两个独立场景，后者先通过实际设置进入最大数量状态。320px 和 390px 的完整场景保留；数量、换行、字体、间距、恢复、缩放、隐私及脚本错误断言均保留，每例仍为 45 秒，不改配置、重试或截图基线。初次拆分后，Edge 与 Windows WebKit 各 16 项通过，均无重试；这不替代完整验收。

头提交 `160acf8` 的[首轮 PR 检查](https://github.com/ZeusCupidCloris/Income-per-sed/actions/runs/41444013166)未通过：Edge 406 项直接通过、1 项原有进度几何用例重试通过；WebKit 304 项通过、16 项缩放排版断言失败、4 项既定跳过，失败在既有自动重试后仍存在，Quality Gate 失败。该结果与本地超时分别保留，不把通过的单项冒称完整检查通过。

# 安装稳定性与浏览器生命周期检查

## 范围

基于本地 main `abde67275f5d2212ac3882a09f4b4451e808ccb5`。本轮只修改维护工具、自动检查及用途索引，不修改四个交付文件，不改变产品版本或交付编号，不创建 Release，不推送 GitHub。

## 安装加固

- npm 安装单次最多 5 分钟，最多 2 次，重试间隔 10 秒；工作流步骤上限 11 分钟。
- WebKit 依赖及浏览器安装单次最多 7 分钟，最多 2 次；工作流步骤上限 15 分钟。
- 超时终止本次安装进程树；Linux WebKit 安装涉及 root 拥有的 apt 子进程，使用 sudo 终止本次创建的独立进程组。清理失败不伪装安装成功。
- npm 网络请求自身也有超时及有限重试。重试只用于安装，不增加页面测试重试或绕过质量门槛。
- Quality、Pages、Release 三处入口保持一致。页面测试和部署门槛不变。

Windows 实际 npm 安装入口通过。5 项安装工具测试包含真实等待子进程的超时终止；发布工具检查为 Python 6 项、Node 14 项，文档检查器 9 项通过。Linux apt 网络故障和 GitHub 步骤超时仍需下一次远程检查验证，不能把 Windows 结果当作 Linux 实测。

## 浏览器证据与限制

新增 `browser-lifecycle.spec.js`，默认同时测试 Develop 与 Push：

1. 真正进入 BFCache 冻结，记录原生 freeze/resume 事件及计时器读数；连续 3 轮返回，断言冻结期间计时器没有推进，恢复后继续推进。
2. BFCache 真冻结结合模拟 5 小时墙钟差，覆盖上午到下午、跨午休恢复；要求实际有连续追赶阶段，不能直接跳到终点；两段进度顺序与拨钮对齐。
3. 原生 `pageshow.persisted` 必须为 true，文档随机身份必须保持；重新加载不算缓存返回通过。Develop 生命周期不得销毁，恢复后为 active。

本地 Edge 新增 6 项及原有进度、恢复组合、背景循环共 42 项通过；强化连续追赶断言后，两个跨午休场景再次通过。恢复采样 JSON 保存在自动测试输出中，不作为长期历史文件提交。

WebKit 原有背景循环、进度与恢复组合 36 项通过；新原生 freeze/resume 专项为 Edge 覆盖，没有将 WebKit 的模拟恢复写成原生冻结通过。四个交付文件、发布清单和 SHA256SUMS 与基线 Git 字节一致，用途索引覆盖本轮 111 个文件。

当前 Edge `154.0.4258.48` 的 `Page.setWebLifecycleState` 调用返回成功，但测试中未暂停计时器、未触发原生冻结事件。因此没有把该接口调用写成冻结通过，改用实际 BFCache 冻结证明；独立后台标签页的强制冻结仍需另行验证。导航到第二个收入页面会因多窗口广播让缓存页被驱逐，属于正常浏览器行为；测试导航到静态校验文本，未关闭产品广播协议。

这里的冻结是真实浏览器冻结；5 小时差是测试注入，不是电脑实际休眠。实体电脑休眠、实体 iPhone/iPad及真实跨夜未在本轮验收，真实跨夜继续暂停。

## 下一步动效研究：尚未实施

以下数值为拟议起点，不是已校准参数或客观质量标准。

### 果冻按钮

- 参考 [CSS 果冻按钮原作者范例](https://codepen.io/donnyburnside/pen/JpgoVN)、[橡胶轮廓按钮原作者教程](https://cloudfour.com/thinks/rubber-button/)、[Motion 官方按压示例](https://motion.dev/examples/js-press)。
- 推荐先做轻触感：按下立即压缩约 2%–3%，松手 260–320ms 内回到原尺寸，仅一次弱回弹。业务动作立即执行，不等待按钮动画。
- 优先选快速回溯入口或设置主按钮中的一个试点。不对时间文本、表盘指针、滚轮、信息卡或整页添加弹跳。
- 按钮点击区域保持不变，只动内部视觉层；连续点击或反向按压从当前状态接管，不能反复从关键帧起点播放。
- 减少动态效果模式取消形变；保留键盘焦点、取消按压、多点触控和禁用状态。引用范例只供研究，移植前核实许可证。
- CSS 交叉缩放最轻量，但文字也会被挤压；SVG 路径形变更接近真实果冻，兼容与材质维护成本较高；小范围原生 Web Animations 按压更容易融入当前单文件。不建议为一个按钮引入框架或动画库。

### 卡片一镜到底展开

可行性判断基于现有两个可编辑卡片共用 settingsDialog、已有开合代次和焦点管理；尚未制作或验收原型。

- 推荐“每小时收入”卡作为首个试点：卡片玻璃外壳从原位置连续扩展成收入设置面板；关闭时沿原路径回到该卡，而非旧卡消失后另弹一个窗口。
- 桌面保持周边网格布局不变，移动端展开到现有安全区内的设置面板。原卡保留占位，不让周边卡片重新排版。
- 初始考虑展开 300–360ms、收回 220–280ms，单一连续轨迹，无大幅回弹。只变外壳、圆角和阴影，文字及输入框不随整壳拉伸；内容在扩展过程中清楚接管。
- 采用 [FLIP 思路](https://gsap.com/docs/v3/Plugins/Flip/)和[原生 Web Animations](https://developer.mozilla.org/en-US/docs/Web/API/Element/animate)实现局部共享外壳优先，不必须引入 GSAP。
- [View Transitions](https://developer.chrome.com/docs/web-platform/view-transitions/same-document)也可用于共享元素，但当前主题切换已经使用它；需要处理转场互斥、快照与中途接管。主仪表持续运动时，局部真实外壳通常比整页快照更适合作为首个原型。
- 保留已有背景隔离、焦点锁定、Escape、持久化反馈及手机安全区。打开中途关闭、关闭中途打开、窗口调整、后台恢复均从当前可见状态继续；旧回调不得隐藏新面板。
- 先只交付 Develop 试点，不自动影响 Push、手册或小组件。验收特别检查文字模糊、面板边缘裁切、页面跳动、主题切换冲突及重复动画资源。

建议先做共享卡片展开，再决定是否加入轻果冻按钮，避免两种新动效同时上线而难以判断手感来源。

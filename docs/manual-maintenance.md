# 说明书校验维护

说明书中的三个源文件校验值由不可见的 Word 书签定位，不再依赖段落位置或哈希出现顺序。

| 文件 | 校验书签 |
| --- | --- |
| Income-per-sed-Develop.html | income_sha256_develop |
| Income-per-sed-Push.html | income_sha256_push |
| IncomeWidget.js | income_sha256_widget |

每个书签只圈定对应的 64 位 SHA-256 文本；允许文本分散在多个文字片段中。移动段落时必须一并保留书签起止位置。其他章节、图片、目录与书签不参与校验值替换。

`npm run release:prepare` 按文件名更新上述位置；`npm run validate` 使用相同标记核对实际文件内容。缺少、重复、未知或未闭合标记，以及圈定内容不是一个完整哈希时，都会报错。其他位置出现的哈希不被改写。

旧版没有标记的说明书不会被自动猜测匹配。先确认每段哈希对应文件，在 Word 中选中哈希文字，按表格名称插入书签，再执行构建。不要将损坏标记的文档直接替换为旧版无标记文档。

测试包括段落顺序调整、文字片段拆分、重复或缺失标记、无关哈希保留、重复运行不产生变化，以及其他压缩包成员与 XML 原内容保留。文档自身的校验值仍放在外部 `SHA256SUMS.txt`，不嵌入自身。

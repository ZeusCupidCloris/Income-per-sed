## 追踪对照

先固定八组，各自独立进程和浏览器、最多十二轮，每轮 45 秒，第一处失败即停止本组，不重试或追加轮次。六组使用纯 JS 记录回调，比较完整追踪、无截图、无 DOM 快照、只记调用元数据及完全不启动追踪；首尾两组完整追踪参照。另两组无自定义循环，分别开启与关闭完整追踪。

时钟辅助、主题、返回实时、390 → 768 → 390、等待、共同克隆/缓存种子和最终检查均保留。关闭追踪选项不是关闭产品动画；完全关闭追踪的组没有 `.zip` 是预定行为，仍保留普通报告、错误事件及驱动日志。不能据此改变正式质量关卡的追踪配置。

| 纯 JS，参照 A | 截图 + DOM 快照 | 12 / 12 | 未崩溃 |
| 纯 JS | 无截图，保留 DOM 快照 | 12 / 12 | 未崩溃 |

实际解析归档核对开关：无截图组的截屏帧为零，无快照组的 DOM 快照为零，仅元数据组两者均为零但保留 API 调用；关闭追踪组没有归档。不是只看配置字段就认为隔离成功。

结果进一步证明自定义采样循环不是必需触发条件，但不能认定追踪是根因：纯 JS 完整追踪参照也十二轮未崩溃，且每组次数有限。源码、渲染路径、时钟辅助与宿主环境仍可能有交互。原始失败和反例均保留，不用关闭追踪取得的结果替换正式验收。

这里两组 `native-*` 是历史诊断文件名，实际只表示“无自定义采样循环”，不表示浏览器计时 API 未包装；八组均使用同一固定业务时间辅助。避免根据组名扩大结论。

## 时钟前提核对

本机 Playwright 1.62.1 的 `setFixedTime` 会经过 `_installIfNeeded`。在 Edge 156.0.4314.42 和 WebKit 26.5 的空白页分别保存原函数引用后执行核对，Date、setTimeout、requestAnimationFrame、performance 及 performance.now 的身份均发生变化；50 毫秒定时回调和动画帧仍执行，等待 150 毫秒后单调时钟分别推进 160 / 164 毫秒。

因此“回调仍运行”不能写成“接口完全原生”。已更正两份旧维护文档的对应措辞，保留原始结果；原测试、依赖和驱动未修改。版本固定的实现见 [clock.ts](https://github.com/microsoft/playwright/blob/v1.62.1/packages/playwright-core/src/server/clock.ts) 与[注入时钟](https://github.com/microsoft/playwright/blob/v1.62.1/packages/injected/src/clock.ts)。这只确认了共同环境因素，尚未证明时钟包装导致崩溃，CSS 动画与 ResizeObserver 也没有被本实验禁用。

## 选择器与关键帧审计

用现有 HTML 解析器、Clean CSS token 和 Acorn 分析十九个样式块及四个脚本，未新增依赖。普通规则 1,997 条、选择器分支 2,584 条，相同选择器及条件组重复 224 组；该口径不把关键帧步骤算作普通选择器，与历史清理计数不能直接混用。

脚本有 183 处 classList 操作，其中 30 处包含非字面参数。静态 DOM 查询不匹配还可能来自隐藏面板、运行时创建、伪状态或动态类，不是删除证据。本轮未按重复或当前不匹配批量删除选择器。

关键帧有 27 份定义、25 个名称，两个名称各重复一次。两份早期定义和后定义均为无条件规则，样式标签没有媒体限制；未找到脚本增删 CSSOM 规则或创建样式标签的入口。规范规定同名关键帧采用后定义，参见 [CSS Animations](https://www.w3.org/TR/css-animations-1/#keyframes)。

| 可先处理的局部候选 | 早期行 | 保留的后定义行 | 隔离实测 |
| --- | ---: | ---: | --- |
| `settingsSheetIn` 的早期定义 | 644 | 7509 | 实际起点为后定义的 `translateY(6px)`，没有早期缩放 |
| `statusEnter` 的早期定义 | 887 | 7484 | 实际起止 filter 均为后定义的 `none` |

Edge / WebKit、390 / 1440、浅 / 深色共八个隔离场景均核对 CSSOM 定义与真实动画关键帧。产品脚本在这些审计页面中禁用，只为探针元素指定动画；探针不是产品里的使用证明，也不是全页交互验收。

`settingsSheetIn` 和 `historyQuickPanelIn` 另有静态零字面消费命中，但这只能进入后续候选队列，不顺带扩大首批删除。初稿曾将 `blend.animation` 的 WAAPI 句柄赋值当作可能的 CSS 写入，已更正并保留初稿；更正后未找到 CSS animation/name 动态写入，不据误报删除代码。

## 测量与写入的已有机制

当前已有 `enqueueDomMutation` / `readPendingDomValue` 统一提交，以及文字、属性、样式和 transform 的 `IfChanged` 检查；拨盘已有坐标缓存和视口失效测试；普通工时与月累计共享整秒/状态样本。不再仅凭函数调用频繁就建设第二套缓存或全局节流。

`className` 被刻意保留为即时写入：动画依赖随后执行的 classList 操作，延迟提交可能把刚添加的状态覆盖掉。历史、启动、返回实时和后台恢复也需要连续读数采样，不能把普通文字的整秒门控扩大到机械运动。后续算法修改必须有真实时钟下的耗时样本与行为证据，不能把自动化操作等待时间直接当作页面函数耗时。

另在完整基线结束后单独采样一次 Edge 桌面页面，不调用 Clock API；核对没有 `__pwClock`、RAF 与 setTimeout 为原生函数、正常工作中且时钟实际推进。使用隔离的合成工资和全天工时，不读取个人存储。CDP 计数器与 1 毫秒 CPU 采样记录如下：

| --- | ---: | ---: | ---: | ---: |
| 工作中 | 10.00 秒 | 381.4 毫秒 | 7.1 毫秒 | 183.8 毫秒 |
| 打开回溯、后退、返回实时、关闭 | 8.26 秒 | 483.2 毫秒 | 61.5 毫秒 | 330.3 毫秒 |

这些列是计数器增量，不按互斥分类相加，也不代表用户按下按钮要等待的时长。CPU 自身采样中，工作阶段 `updateTimelineChrome` 约 40.7 毫秒；回溯阶段 `position` 约 34.6 毫秒；收入阶段 `updateIncomeModeIndicator` 约 21.2 毫秒。样本数不是调用次数；只有一次、一个桌面浏览器且包含采样开销，不是设备性能排名或优化前后对照。

源码对照后，普通时间/无障碍文字同步、已有定位缓存的写入失效边界、收入指示器的布局读取值得后续定点核对；不能把这些小样本直接定为主要瓶颈。尤其 `position` 已有视口签名缓存，应先确认重复入口及失效条件；不叠加第二套坐标缓存，不直接降低动画更新频率。本轮未按采样结果修改算法。

## 什么时候可以改文件

- 文档、诊断与独立测试可以现在改，本轮已经这样做；原断言、容差和负面证据不删除。
- 为保证可比性，完整基线运行期间不改这份被测产品文件。基线结束后，可以立即开始上表两处早期关键帧的独立本地清理预览，不需要等未知崩溃全部归因才允许任何产品修改。
- 第一批只删两份被覆盖的旧定义，保留后定义、所有实际动画参数和脚本；从 Develop 编辑并生成独立 Push，验证有效关键帧、正常开合/状态切换及新旧对照。收益是维护清晰，不承诺可感知提速。
- 主题、滚轮、缩放和运动算法暂不与这批混改。需要明确的前后行为证据或可验证热点，再有针对性修改；不能继续猜一条 CSS 或通过关掉观测隐藏问题。
- “能做本地预览”不等于“能合并发布”。交付仍须原完整关卡、构建/四文件一致性以及对残余稳定性风险的明确处置；正式检查失败时不直接推 main。用户暂缓的真机/整夜验收不擅自标记完成。

当前冻结的是相关高风险路径和待验收交付，不是整个仓库。先固定基线，再一批一批做可解释的局部改动，避免诊断变成没有出口的全局冻结。

本轮结束后，下一次产品修改可立即从两份早期关键帧的隔离预览开始；这不是已经执行了删除。稳定性下一步只做与原业务时刻、动作相同、仅替换业务 Date 的有界对照，保留原生计时/RAF，并验证实际函数身份；原正式用例继续保留。先验证这个新线索，不再无边界扩展主题、CSS 或采样组合，也不以对照未崩溃冒充正式关卡通过。

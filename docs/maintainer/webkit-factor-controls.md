## 实验边界

Windows、Playwright 1.62.1、WebKit 26.5，保留该版本默认启动参数、原生动画帧及 ResizeObserver。金额、固定业务时间、390 → 768 → 390、回溯滚轮操作及 350/700/4600/600 毫秒等待均保持一致；每轮仍以 45 秒为上限。实验组逐个启动独立浏览器进程，没有浏览器组并发。

先将六组顺序和预算写入 `plan.json`，首尾两组为原流程参照；其他组每次只改变一个目标因素。每组至多六个新上下文，第一次出错即停止该组、保留未执行轮次，不进行测试重试。前置负载为克隆收入 DOM/CSS 后进行十二轮同页循环，仍保留原采样、交替主题和返回实时。这里的“无前置负载”同时省去克隆和十二轮循环，不能仅归因于循环次数。

关闭目标采样只移除自定义逐帧几何/样式读取及记录，不移除追踪快照或产品自己的观察器。不切主题采用同一控件的 Home 键维持浅色；不返回实时用空求值替代那一次点击，仍保留后续等待。操作耗时另行记录，但这些反事实不会完全匹配原流程的按键、布局查询、分配和时序开销。

## 可以与不能得出的结论

- 本轮十一组共捕获五个页面 `crash` 事件，原始日志与追踪全部保留；不是把一个事件的多条错误当作多次崩溃。
- 五次均处于恢复 390 像素阶段。协议中的缩放调用已完成，约 258–288 毫秒后阶段标记求值返回 `Target crashed`；不能据错误落点认定赋值本身是根因。
- 单页第一轮也会失败，因此十二轮预热不是本次现象的必需条件；该组仍有一次克隆前置，不能写成完全没有额外观测。
- 不点击返回实时仍触发崩溃，因此返回实时不是必需触发步骤，暂不针对播放或实时按钮改动画。
- 去掉采样、不切主题的同页组各十二轮未崩溃，值得优先研究主题变化、布局/样式查询与缩放的交互；但原流程参照 B 也十二轮未崩溃，不能据此证明因果或排除任一因素。
- 尚未取得有效独立最小复现或原生堆栈，不能将间歇性问题标为已修复，也不能断言普通用户流程没有风险。

五个准确 UTC 窗口的 Windows Application 1000/1001 查询均无匹配记录；默认 CrashDumps 目录未发现匹配 Playwright / WebKit / MiniBrowser 的转储。查询无匹配不等于没有原生问题。初次查询因日期自动转换而使用错误时区，已另存并废弃，只以保留 UTC 字符串的更正查询为证据。没有修改注册表、开启全局转储或安装调试工具。

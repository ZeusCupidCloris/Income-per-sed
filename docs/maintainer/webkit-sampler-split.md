# WebKit 逐帧采样拆分

日期 2026-10-26，基准 `52da977`，承接[单因素对照](webkit-factor-controls.md)。本轮只运行隔离诊断并记录结果，产品文件、原测试/断言、截图基线、配置和依赖不改，不升级或发布。真实手机与真实整夜验收继续暂缓。

## 预定范围

首轮五组，每组独立进程/浏览器、最多十二轮，首尾为完整采样参照，中间为位置尺寸、计算样式、仅记录三组。共同保留主题、返回实时、390 → 768 → 390、固定业务时间、原生动画、追踪、DOM/CSS 克隆及每轮 45 秒上限。第一次失败立即停止该组，不重试或追加轮次。全部组之后单独执行原长金额失败用例一次，原测试内容不变。

采样使用相同 RAF + 延后任务、字段、逐节点数组和写盘路径。每轮开始共同读取一次缓存种子；位置组逐帧读取元素边界及文档宽度、使用缓存位移，样式组读取计算位移、使用缓存边界，记录组两者均用缓存。缓存值不能作为该帧实际布局或运动证据。各组仍有共同的 `innerWidth` 视口替换保护及节点选择。

记录实际帧数、序列化字节、几何/样式读取计数，不声称 CPU、分配和输出字节完全等量。几何组只验证实际几何，样式组只验证实际运动；所有组最终都读取真实边界和状态。反事实组不能替代原始验收。

新版完整采样也增加了共同缓存种子和分配路径，因此不是上一轮采样器的逐字复制，独立原始用例控制必须单列。

## 补充范围

首轮记录组仍可能受视口读取和节点选择影响，故再预定三组各至多十二轮：保留共同读取的记录参照、回调内无节点选择/视口/元素几何/计算样式读取的纯 JS 记录、无自定义帧循环。共同的初始/最终读取、产品自身观察器和追踪保留。

纯 JS 记录使用固定缓存数组长度，不再跟随 DOM 节点数变化，因此只保证名义字段及记录规则相近，不保证完全等负载；无循环组有意没有逐帧记录。两轮计划及原始证据分别另存，不补跑前轮失败。

## 负载与解释

完成轮次的自定义记录约为每轮 235–285 帧。各组逐帧字段、对象形状、数组规则和写盘路径一致，但平均记录大小约为每帧 1,127–1,338 字节；纯 JS 组使用固定缓存节点数，其他组随当前 DOM 数量变化。这不是等字节、等分配或等耗时实验，不据此计算崩溃率或性能排名。崩溃轮未返回的帧数据不记成“没有执行采样”。

逐轮核对实际读取计数、记录字节数、真实最终边界、实时状态和主题；缓存几何/位移只证明名义负载，不能证明该帧真实布局。没有将反事实组缺少逐帧几何或运动断言的结果冒充原测试通过。

四次崩溃都出现在恢复 390 像素阶段，缩放协议已完成，约 232–291 毫秒后的阶段标记求值返回 `Target crashed`。这是页面崩溃事件与协议错误，不是金额计算或几何断言失败；阶段标记不是据此认定的根因。

纯 JS 记录也失败，说明自定义采样持续读取元素几何、计算样式并非本次现象的必需步骤，不能把原因简单锁定在某个读取 API。共同的初始/最终读取、主题和缩放、产品观察器、追踪及宿主环境仍在；完整采样与记录参照又有未崩溃反例。当前只获得了优先排查观测/记录调度与渲染交互的线索，尚未取得可归因的原生堆栈或有效独立最小复现。

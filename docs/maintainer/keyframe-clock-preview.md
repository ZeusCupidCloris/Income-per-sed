## 重复读写核对

在一次 Edge 桌面合成工作状态中，对内存服务副本加函数入口计数及 DOM 读写探针，不保存到产品文件，不使用 Playwright 时钟。统计窗口从面板稳定后开始，排除开合动作；探针会增加开销，只用于次数，不作为函数耗时或优化前后性能对比。

| 稳定观察窗口 | 实际时长 | 顶部同步次数 | 每个目标 aria-label 写入 | 每个标签内容未变的写入 |
| --- | ---: | ---: | ---: | ---: |
| 工作中 | 6.01 秒 | 365 | 365 | 359 |
| 实时状态下回溯面板打开 | 4.00 秒 | 244 | 244 | 240 |
| 收入面板静止 | 4.01 秒 | 243 | 243 | 239 |
| 工资输入后静止 | 4.00 秒 | 244 | 244 | 240 |

两个目标是 `currentTime` 与 `liveAnchor` 的 aria-label，源码在 `updateTimelineChrome` 中直接 setAttribute。六秒窗口内二者合计 718 次写入内容未变，下一批可以仅将这些直接写入接入已有 `setAttributeIfChanged`；同秒中历史状态变化仍应立即更新，不先加整秒总开关或第二份缓存。

相同窗口内 `currentTime.datetime` 持续变化，不能把它视为重复内容而砍掉毫秒更新。工时进度尺寸读取在该样本约为每秒一次；`position`、`reposition`、`schedulePosition`、`updateIncomeModeIndicator` 在四个稳定窗口均未执行，不能据前轮短时开合 CPU 样本把它们误判为每帧常驻瓶颈。开合与失效阶段仍可能有其他可优化点，本次没有据静止窗口结论新增布局缓存。

提示文字的 setLabel 调用较多，但已检查内容是否变化，不能把调用次数当成相同数量的实际写入。本轮只核对，未扩展产品补丁到格式化、属性写入或定位算法。

# 工作时间校验入口迁移

从[工时滚轮迁移](schedule-wheels-twenty-second-batch.md)继续。原 280 个项目文件与该轮本地存档逐字节一致。

[面板校验](../../src/components/schedule-settings/validation.js)统一计算上午与下午时长，并返回按原顺序发现的首条违规。摘要、提交前检查、日历操作后的保存状态共用该入口；一次编辑中复用判定，不新增跨事件缓存。原提示、焦点、播报、底层保存校验和日历回滚仍由宿主处理。

## 验收范围

在桌面开发版与窄屏发布版分别核对：开始等于结束时，摘要先显示「等待校准」，首次点保存才标出错误并阻止写入；激活校验后，午休重叠会即时标出但不抢焦点；上午结束恰好等于下午开始时允许保存，刷新后应保留工时。源码用例另覆盖下午开始等于结束和多处违规时的提示优先级。

## 验收结果

- 拆分前 Edge、WebKit 各 2 项边界用例通过；拆分后各 24 项专项通过，零重试、零跳过。包括原提示时机、焦点、修正保存、草稿恢复、日历失败回滚及两份单 HTML 离线使用。
- 256 组代表性时间组合的新旧时长、有效性、首个违规字段和文案一致。还原旧校验接线后，开发版与上一轮逐字节一致，保存和备份校验未改。
- 源码检查 46 项通过，构建内联 57 个源文件。8 张工时面板截图对照和原有 8 项 Edge 视觉检查通过，未更新基线。

本次只生成本地候选，未做全量验收，不升版、不发布、不替换桌面文件。

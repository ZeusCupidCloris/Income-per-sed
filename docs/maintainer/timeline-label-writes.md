# 顶部标签的重复写入优化

日期 2026-10-26，基准 `5387133`，承接[旧关键帧与读写核对](keyframe-clock-preview.md)。本轮只优化 `currentTime` 和 `liveAnchor` 的 aria-label 提交方式，保留实际文案和交互。本地候选仍为 2.7.2，不升级版本、上传 GitHub、部署 Pages 或替换桌面文件；真实手机、VoiceOver 与真实整夜验收没有完成。

## 产品改动

`updateTimelineChrome` 中六处时间标签分支和一处返回实时标签，从直接 setAttribute 改为已有 `setAttributeIfChanged`。精确文本重建证明只有这七个调用点变化，原参数表达式全部相同；helper、毫秒 datetime、指针、滚轮、状态机、格式化及缓存代码不变，Develop 和 Push 的 CSS 均逐字节不变。

不增加整秒总开关：相同时间文字下，暂停、衔接播放、播放、拖动和返回实时仍有不同完整文案，按值比较会立即提交。状态机原有的即时提示写入仍保留，没有扩展到其他属性或 aria-live 设置。外部临时改错标签后，下一次同步仍读取真实值并恢复，不另建长期标签缓存。

Develop 从 1,087,840 增至 1,087,910 字节，增加 70 字节；Push 从 619,552 减至 619,482 字节，减少 70 字节。主要收益是减少无变化写入，不以源码删行数或文件尺寸推断速度。

## 实际写入量

修改前后分别运行一次相同的 Edge 桌面原生时钟诊断，使用合成工资和全天工时；在内存服务副本中加函数入口及 DOM 探针，不改产品文件。稳定观察窗口不含开合动作，探针本身有开销，因此只比较次数，不据此宣称 CPU、帧率或按钮延迟按同比例改善。

| --- | --- | --- | --- |
| 工作中 | 6.006 / 6.016 秒 | 366 → 6 | 360 → 0 |

六秒窗口中，顶部同步调用前后为 366 / 367 次，datetime 的变化写入为 360 / 361 次，没有改成每秒才同步整个顶部。两次观察不是相同时刻或等量 CPU 实验，时钟边界及帧数允许自然差异；相同内容的标签写入归零才是本次直接证据。

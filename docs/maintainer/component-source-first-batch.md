## 已实施范围

- [src/page.html](../../src/page.html) 是唯一源码入口，保留尚未迁移的原有代码；Develop 和 Push 均由源码组装，不再手改。

- 首次物理拆分时，组装结果与原 2.7.6 Develop 逐字节一致。随后只重写本卡片的边界及少量接线，时钟、保存、计薪与机械运动代码不重写。
- 专属 CSS 按原位置装回，保留选择器、媒体查询、顺序和优先级。包含其他卡片的共享规则仍留在模板中，不拆散或复制。
- 组件接收根节点、商品与显示收入，私有保存数量节点；不读取全局配置、不访问存储、不新增时钟、缓存或状态总线。
- 原离线四文件名称不变，运行时无需源码目录。新增外部脚本或样式依赖会被发布检查拒绝，并使用实际离线 HTML 入口验证。

## 维护入口

`npm run build:develop` 只生成可读的单 HTML。`npm run build:push` 同时生成 Develop 和 Push。`npm run build:check` 只检查当前源码与两个产物是否一致。`npm run source:locate -- <行号>` 回查生成行的真实源文件，不冒称浏览器标准 Source Map。

完整交付生成仍用 `npm run release:prepare`：组装 Develop、压缩 Push、同步手册校验值及外部清单。原耗时比较工具改为调用同一个纯压缩函数在内存生成比较结果，不再复制旧构建脚本或临时改写交付文件。

显式写入流程 `quality:local` 改为先生成、再运行原有检查。源码组装测试会检查已生成页面的一致性，因此不能在更新源码后、生成页面之前运行该断言。三个只读检查入口仍不生成文件，所有原断言、浏览器范围与失败关闭行为保留，另加命令顺序契约。

## 验收边界

新增组装测试覆盖顺序、片段完整性、循环、重复、越界路径、Windows 路径别名、只读检查和源码定位。新增组件浏览器检查覆盖实例隔离、数量边界、无重复写入、挂载/销毁、日期标题，以及实际 Develop/Push 离线入口。

已有业务、长内容、动效和截图测试继续保留；不改原阈值、45 秒上限、重试配置或既定跳过。真实设备、真实跨夜和实际读屏仍未验收。

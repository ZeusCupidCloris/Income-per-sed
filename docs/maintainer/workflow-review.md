## CI 是什么

CI 是持续集成：提交后自动在干净环境安装依赖、检查构建和运行测试。它可以阻止混版、存储回归、布局越界或错误产物进入 main；Pages 则负责将通过检查的页面发布到线上。它不能证明实体 iPhone 或真实跨夜通过。

## 五类覆盖与浏览器职责

| 类别 | Edge | WebKit | 保留理由 |
| --- | --- | --- | --- |
| 计算与存储 | 小组件算式、网页存储异常；小组件替身另在快速检查 | 网页存储异常 | 算式不重复搬到两个引擎；浏览器存储行为分别验收 |
| 恢复与回溯 | 全量输入、跨日期、生命周期、恢复组合 | 进度、读数、跨日期、恢复组合等既有子集 | Edge 的 CDP 冻结不能假称 WebKit 实机；共有恢复故障保留双引擎 |
| 设置交互 | 路径、文字、手势、清理、焦点、最后一帧 | 文字、滚动条、细节、输入安全等既有子集 | 最近问题集中于引擎差异和交接帧，暂不削减 |
| 布局与视觉 | 截图基线、长金额、网格 | 手机边界、长金额、网格 | 像素基线不在不同引擎间直接复用；布局边界双引擎保留 |
| 发布一致性 | 生成规则、文档等非浏览器快速检查；双版本网页行为 | 双版本网页行为 | 源文件与生成产物必须分别验证 |

权威功能归属为[五类测试表](../../config/test-groups.cjs)，实际 WebKit 范围为[浏览器配置](../../config/playwright-webkit.config.js)，不另复制文件名单。

## 阶段职责

| 阶段 | 当前检查 | 决策 |
| --- | --- | --- |
| PR Quality | 发布一致性、Edge、WebKit | 保留，阻止问题合并 |
| main Quality | 同一检查验证实际合并提交 | 保留；不能仅凭分支已通过认定合并结果相同 |
| Pages | 同一 SHA 生成且无差异、部署、线上字节核验 | 保留；重复生成耗时较小，暂不增加证据复用协议 |

本轮默认浏览器收集限定为 `*.spec.js`，避免 Node 单元测试在 Playwright 收集时再次执行；Node 单元测试仍由快速检查及 CI 发布任务完整执行。独立帧开销采样文件改为手动 `test:observe`，不是取消功能检查；同时核对布局读写顺序的混合用例仍保留。三项必需检查名称仍保留，`WebKit smoke`是历史名称，实际是兼容性回归，不是仅检查页面能否打开。

## 2026 年 10 月 8 日改动分流

本次维护不修改四文件，也不删除测试；在原有任务之前增加比较步骤和 Quality Gate。PR 比较目标分支基线与实际测试提交，main 比较本次推送前后；手动触发默认完整验收。比较不可用、解析失败、未知文件或多个浏览器功能组共同变化时默认完整验收。

| 实际变化 | 自动选择 |
| --- | --- |
| 仅小组件与既有小组件测试 | 小组件配置、布局、发布一致性与 Edge 三项网页/小组件日历、计算、金额格式对照；不启动 HTML 全套 |
| 首页、手册或图片说明 | 文档、图片与发布一致性，不启动 HTML 浏览器套件 |
| 仅版本元数据 | 发布一致性，不启动 HTML 浏览器套件 |
| 一组已归属的浏览器测试变化 | 该组 Edge 与既有 WebKit 兼容范围 |
| 两个明确 UI 函数的字面量微调 | 设置专项；其他控制流、调用、运算与标识符变化均全测 |
| 真实网页结构、CSS、共享逻辑、构建、依赖、工作流或未知变化 | 原有完整 Edge 与 WebKit 验收 |

HTML 只排除唯一发布对象中经过验证的四个字符串字段，不排除整个对象、脚本或文件。软件包与清单也只允许已定义的版本字段变化，依赖与命令变化不走捷径。Push 必须由 Develop 可重复生成；局部 UI 修改的压缩产物由必需发布验证核实，不能独立改 Push。

局部 UI 字面量范围仅为 `updateIncomeModeIndicator` 与 `updateScheduleCalibrationSummary`，避免凭改动行数或提交标题猜测风险。既有全量入口保持可用；此名单不是扩大局部重构的许可。

原三个必需结果仍出现：不需要浏览器套件时只省略安装和执行，明确写出原因，而非伪称浏览器验收通过。Quality Gate 逐一要求分流、发布验证及两个浏览器任务成功；失败、取消、跳过或缺失均阻止部署。合并保护增加该汇总结果，不移除原有检查。Pages 仍按同一 SHA 验证首页与 Push 字节。

本次通过现有工作流约束测试补充反例，没有另建重复测试目录。分流工具和工作流自身的维护提交属于全测，必须先通过远程完整检查，之后小组件交付才按新规则验收。本地真实 2.6.1 相对当前 main 的差异已判定为小组件范围；远程结果仍以实际运行记录为准。

- 不缩减存储、恢复、长金额或最后一帧断言，不增加重试掩盖失败。
- 不重建截图基线。

上一轮两次完整回归分别约 15–17 分钟；PR 与 main 串行增加发布等待。当前收益优先来自减少收集副作用、统一入口及清理重复初始化，不承诺本轮能把完整回归压缩到几分钟。

本轮优先验证分流正确性，暂不继续合并测试或调整动效。
